## 1.0.8 (unreleased)

- **Defaults match the SpacePixels profile (behaviour change).** `new DetectionConfig()` now gives the values SpacePixels ships and the reference regression uses, so the library, the application and its example profile start from the same settings. Seven defaults change: `detectionSigmaMultiplier` 5.0 → 3.5, `growSigmaMultiplier` 3.0 → 2.75, `masterSlowMoverSigmaMultiplier` 4.0 → 3.5, `masterSlowMoverGrowSigmaMultiplier` 3.5 → 2.75, `maxStarJitter` 1.5 → 1.0, `enableVariableStarDetection` false → true, and `enableFaintMoverSearch` false → true.
  - *Effect.* A configuration that sets these fields explicitly is unchanged. One built from the defaults now detects fainter sources and runs variable-star photometry and the experimental faint-mover search. That search adds run time, bounded by `faintMoverMaxSeconds` (10 minutes by default), and skips itself without capture times or with fewer than 8 frames. Set the two switches to `false` for the earlier, faster behaviour.

- **Faint-mover few-frame check (new setting, on by default).** `enableFaintMoverFrameLimit` rejects a faint-mover candidate whose score comes from a few frames. Each frame's contribution along the path is capped at the path's median unmasked frame plus 3 frame noises, and the capped score must still reach `faintMoverMinScore`. `FaintMoverSearchTelemetry.rejectedFewFrames` counts these, and the text report shows them as *few frames*.
  - *Why.* In a 68-frame session, every star in a run of eight frames had a faint one-sided tail, as from a gust of wind or a mount movement, and those frames passed quality control. The tails of bright stars reached past the search's star mask and gave 200 false candidates.
  - *Effect on the reference data.* With the shipped profile (search off), the 18 reference datasets give the same results; only the new setting is added to the configuration. With the search on (a five-minute limit), 16 of them keep every candidate but one: a borderline candidate in helix-reg (score 8.03, halves 3.1 and 8.9) whose strongest five frames hold 62% of its signal. On crops of the reference data, the 68-frame session falls from 174 candidates to 1, and klangwolke-2 keeps its 10 known candidates with unchanged scores. Injected movers are recovered as before (25 of 35 in quiet sky, 12 of 12 passing a bright star), while other candidates on the injected crop fall from 102 to 2.
  - *Limitation.* A residual that a third or more of the frames share is not stopped; a frame check for that case is proposed as [SM-F8](FEATURE-REQUESTS.md#sm-f8-frame-check-for-runs-of-leaky-frames).

- **Local-rescue repeat minimum.** Local repeats now require at least three detections instead of two. This remains a detection-count check; proximity clusters may contain several detections from one frame. Moving rescue classes retain their four-detection minimum. Photometry settings and defaults are unchanged.

- **Standalone frame quality control (additive API).** `JTransientEngine.evaluateFrameQuality` accepts an in-memory list or an input count and stable concurrent `FrameLoader`. Both share detection's exact quality measurements, session thresholds, registration/coverage exclusions and rejection priority, without transient extraction, stacks, linking or photometry. The detached immutable `FrameQualityResult` describes every original frame, including rejected ones, unavailable limits and padding-edge registration fits. Streaming uses two reads per frame with bounded worker image memory. Existing pipeline signatures, configuration defaults and scientific selection are unchanged.

- **Faint-mover review retention.** The run-owned pixel pool increases to 64 MiB. Detection scores, candidate cutouts and scientific selection are unchanged; unavailable review remains explicit.

- **Faint-search work previews and progress (F28, additive observer contract).** Optional requested snapshots carry copied active-tile/trial-path geometry on an example original frame, without borrowing pixels or treating trials as candidates. Joined workers emit throttled phase-local estimated work and completed-tile counts during long tiles. Existing skip/truncation, cancellation, scientific scoring and selection remain unchanged; `FaintMoverSearch.Input.observer` supports direct callers.

- **Slow-mover temporal review and track correspondences (additive API).** `SlowMoverCandidateDiagnostics.motionEvidence` adds `SlowMoverMotionEvidence` with copied supported centroids, original identities/capture times, descriptive drift/RMS/correlation and explicit clock/support availability. `SlowMoverTrackMatcher.match` adds post-tracking spatial/common-frame distance measurements, excluding ambiguous IDs and conflicting known times. Neither confirms identity, rejects a candidate, changes defaults nor retains source pixel buffers. Broader straight/curved/shuffled controls are documented in the [research archive](docs/research/slow-movers/README.md).

- **Maximum-stack source-row caching (performance only).** The reducer borrows each input row once instead of resolving it for every pixel. Pixel arithmetic, reduction order, output ownership, cancellation and detection settings are unchanged. Full-size isolated benchmarks and the SM-F3 scientific experiments are described in the [research archive](docs/research/slow-movers/README.md); the proposed temporal/shape/residual gates remain experimental.

- **Bounded faint-mover review evidence (additive API).** `FaintMoverCandidate.diagnostics` (`FaintMoverDiagnostics` and its `Frame`) adds copied PSF-filtered residual rectangles, first/second-half maps, original frame identities, actual rounded scoring samples and centre-mask flags. A run-owned 64 MiB pool retains stronger peaks' review pixels while their tiles are resident; at most 128 frames and 256 pixels per side. Resource-limited evidence has an explicit reason and never rejects a candidate. Telemetry adds `diagnosticsAvailable`/`diagnosticBytes`. Treat arrays as read-only and signals as processed evidence, not photometry or calibrated S/N. Scores, cutouts, selection rules and settings retain their definitions; no public signature is removed.

- **Experimental faint-mover search (new stage, on by default; additive API).** `enableFaintMoverSearch` adds digital tracking after residual analysis: the kept frames are shifted along trial motions and added, so point-like movers too faint for the single frames add up. Its candidates are a separate list; no other result changes, and with the switch off every result is unchanged.
  - *Checks.* A candidate must reach `faintMoverMinScore`, be supported by both halves of the session (frames whose path is masked do not count), score clearly above the stationary stack and above the stack at one camera position (hot pixels), and not be a tracked object or a side lobe of one or of a much stronger candidate. Only the session with the most frames is searched when a gap of over two hours separates others.
  - *New API.* `FaintMoverSearch`, `FaintMoverCandidate`, `PipelineResult.faintMoverCandidates`, `PipelineTelemetry.faintMoverSearchTelemetry` (`FaintMoverSearchTelemetry`) and its text-report section, `PipelineTelemetry.Stage.FAINT_MOVER_SEARCH`, `StageId.FAINT_MOVER_SEARCH`, `DetectionConfigRules.Stage.FAINT_MOVERS`, `FrameRegistration.toFrame`, and the settings `enableFaintMoverSearch`, `faintMoverMinDisplacementFwhm`, `faintMoverMaxSpeedPixelsPerMinute`, `faintMoverMinScore` and `faintMoverMaxSeconds`. Saved configurations gain these five keys.
  - *Effect on the reference data.* On Klangwolke-2 it finds all five known asteroids of predicted magnitude 18.5-19.0 that the shipped profile misses, without their predictions, and recovers 80-95 % of injected movers of magnitude 18.0-19.5. Null controls leave about one candidate or fewer per session at the default score. It takes 70-90 s on Klangwolke-2 and up to 300 s on a four-hour session of 106 frames.
  - *Limitation.* Experimental: candidates are unverified, the cost grows quickly with the session length and the speed limit, and uncalibrated data can still give a few hot-pixel candidates.

  See [the algorithm](ALGORITHM.md#faint-mover-search).

- **Slow movers are no longer taken for camera-fixed sources (detection change; additive API).** When the frames move little between exposures, a slow asteroid can stay within the 2 px camera tolerance in several frames, and its detections were set aside as a hot pixel. A group of at least 4 frames is now fitted with a straight line against time twice, on the camera and in the registered frames. When the registered fit's rms is below 1 px and below half the camera fit's, the group follows the sky and its detections stay for linking.
  - *New API.* `CameraFixedRejector.reject(frames, registrations, followingSky)`, and `TrackerTelemetry.cameraFixedGroupsFollowingSky` and `cameraFixedDetectionsFollowingSky`.
  - *Effect on the reference data.* With the shipped profile, Klangwolke-2's two camera-fixed groups were 611 Valeria: its track grows from 16 to 27 frames. The other 17 datasets are unchanged. With the Maximum Auto-Tune configuration on Klangwolke-2, one of 76 groups is released, 9 detections of 4767 Sutoku: its track grows from 14 to 20 frames, and the other three form a local rescue candidate on its path.
  - *Limitation.* On frames that drift steadily without dither, a mover moving with the drift still cannot be told from a hot pixel.

  See [the algorithm](ALGORITHM.md#94-camera-fixed-sources).

- **Brief fadings left by star peaks removed before registration are flagged (photometry change; additive API).** Hot-pixel removal on undersampled frames can take a star's peak pixel for a hot pixel and remove its light. With dithering, a different random subset of stars fades for exactly one pointing each time. On M81 Kumar (2.9"/px, FWHM 2 px) this made 16 of the 18 possible candidates and a high-confidence candidate without a catalogue match.
  - *The check.* Before scoring, each star's brief fadings and brightenings within one pointing are compared with its nearest clean pointings in the frame cutouts. A change counts as concentrated when its lost or gained light sits in the brightest pixel; a real change in brightness scales the whole profile.
  - *The session decision.* When concentrated fadings are at least 20 and at least five times the brightenings plus one, the session counts as affected. Its concentrated fadings are then flagged `PEAK_REMOVED`, left out of scoring, kept for display, and explained in a readiness message.
  - *New API.* `PhotometryFlags.PEAK_REMOVED`, `VariableStarAnalyzer.Input.frameRegistrations` (set by the engine), `PhotometryTelemetry.peakCheckFadings`, `peakCheckConcentratedFadings`, `peakCheckConcentratedBrightenings`, `peakRemovalFound` and `measurementsPeakRemoved`, and `PhotometryFrameStat.peakRemoved`.
  - *Effect on the reference data.* On M81 Kumar, 414 concentrated fadings stood against 17 brightenings, and 625 measurements are flagged. Candidates go from 10/18/22 to 9/9/13 high/possible/rejected. The other nine high-confidence candidates, all VSX-matched, are unchanged. The check finds nothing on the other 17 datasets, whose results are unchanged.
  - *Limitation.* A genuine dimming within one pointing can be taken for one in about 3 % of cases on such data. The photometry stage's run time is unchanged within the machine's variation.

  See [the algorithm](ALGORITHM.md#photometry-11-1).

- **Reported photometry errors include the noise that neighbouring pixels share (photometry change; additive API).** The sky-noise error treats pixels as independent, but registration interpolates the frames, so neighbouring pixels share noise and the errors were 1.1–2.9 times too small even for faint, sky-limited stars. Each frame now measures a factor per aperture on a grid of blank-sky apertures: their noise over the noise the formula predicts, at least 1. `StarLightCurve.magError` includes it, while check B and the SNR cut keep the formula's error; stars, verdicts, scores and candidates are therefore unchanged.
  - A frame with fewer than 50 blank positions takes the session median of each aperture's factor.
  - New: `PhotometryFrameStat.skyNoiseFactor` (main aperture), and `PhotometryTelemetry.skyNoiseFactorMedian`, `skyNoiseFactorMin`, `skyNoiseFactorMax` and `framesWithoutSkyNoiseFactor`, which also appear in the text report.
  - On the reference data the main-aperture median is 1.14 on M81 Kumar and UG 6524, 1.82 on Klangwolke-2, 2.71 on m5-reg and 2.89 on Eagle-noisy; smaller apertures have smaller factors.
  - The photometry stage takes about 0.1–0.7 s longer per session.
  - The errors remain a lower bound: the star's photon noise and the atmosphere are not included.

  See [the algorithm](ALGORITHM.md#photometry-6-3).

- **Outliers on either side of a missing measurement no longer support each other (photometry change).** An extreme point is kept when a neighbouring usable point deviates the same way. The neighbour used to be the next usable point even when the star had a missing measurement in between, so two single-frame deviations either side of a crossing-flagged or contaminated measurement kept each other, scattered the light curve and formed a Stetson J pair. A neighbour now counts only when no used frame lies between the two; a frame left out of the photometry still does not separate them. `VariabilityScorer.FrameSeries` (package-private) gains the used frames. On the reference data Eagle-noisy's only possible candidate, two such deviations around a crossing, becomes constant; M81 Kumar goes from 10/17/21 to 10/18/22 high/possible/rejected and UG 6524 from 0/1/1 to 1/0/2, through their neighbours' statistics; Klangwolke-2 and m5-reg are unchanged. No VSX-matched candidate changed. A rule that broke at time gaps was rejected: on M81 Kumar's burst cadence every high-confidence star would fail PERSISTENCE. See [the algorithm](ALGORITHM.md#photometry-11-1).

- **The APERTURE gate compares the light curves through time (photometry change; API change).** It compared the 5th-95th percentile ranges of the 1.0 and 2.0 x FWHM curves, which passed opposite or shifted aperture curves with equal ranges and failed faint real variables whose noisy ranges differ. It now measures the share of the candidate's pattern by which the two curves differ (the slope of large minus small against the scored curve) and its regression standard error, and fails when that share exceeds `variableMaxApertureAmplitudeDifference` (still 0.3) and two standard errors, or cannot be measured. `StarLightCurve.apertureAmplitudeDifference` is replaced by `aperturePatternDifference` and `aperturePatternDifferenceError`. In controls the gate now catches 94-100 % of opposite or shifted curves (formerly 0-20 %) and fails 0.1-4.4 % of real variables (formerly up to 46 % at low signal-to-noise). On the reference data klangwolke-2 goes from 47/22/29 to 53/16/29 high/possible/rejected (eight possible candidates, three of them VSX-matched, become high confidence; one VSX-matched possible candidate diluted by a neighbour becomes rejected) and M81 Kumar from 9/19/20 to 10/17/21; the other datasets keep their tiers. See [the algorithm](ALGORITHM.md#photometry-11-4).

- **Aperture choice on matched measurements and actual radii (photometry change).** Each brightness range's apertures are now compared on the same measurements (those the main aperture can use and every aperture has), so an aperture cannot win by lacking difficult points. The minimum radius of another aperture is checked on the smallest radius actually used on the frames, at 1.5 px, instead of factor x session guide FWHM at 2 px: the guide overstated the radii in undersampled fields (M81 Kumar's 1.0-FWHM aperture is 1.73-2.41 px against a 2.24 px guide), and a 2 px floor on the actual radii would have cost that session a VSX-matched variable whose smaller aperture measurably lowers the constant stars' scatter. A star whose chosen aperture lacks one of its main-aperture measurements keeps the main aperture; new `PhotometryTelemetry.apertureMainFallbacks` counts them. On the 18 reference datasets every result is byte-identical. See [the algorithm](ALGORITHM.md#photometry-11).

- **Photometry errors use the sky sample that gave the sky estimate (photometry change).** The sky-noise error's count term used every unmasked annulus pixel, while the sky level and noise came from the clipped sample. It now uses that sample's size; `ApertureMeasurer.clippedMedianAndSigma` (package-private) also returns it. Errors grew by a median of 0.01–0.03 % and at most 0.3 % on the reference data; through the SNR and check B precision cuts 14 Klangwolke-2 stars and one Eagle-noisy star are no longer scored, some check B linear ranges moved by up to 0.06 mag, and no verdict or candidate changed. The error remains a sky-noise lower bound. See [the algorithm](ALGORITHM.md#photometry-6-2).

- **The photometry star-cap warning follows check B's count (additive API).** `PHOTOMETRY_STAR_CAP` warned only when `photometryMaxStars` was below `linearityMinStars`. Check B counts stars only up to the 90% brightness rank, so a cap of 50 to 54 passed silently although it can never supply the default 50 references. The warning now applies below `DetectionConfigRules.minimumStarsForLinearityCheck(linearityMinStars)` (55 for 50), or below the ensemble's 10 stars when that is larger, and stays a warning. New: `DetectionConfigRules.LINEARITY_REFERENCE_FRACTION`, which check B now uses, `minimumStarsForLinearityCheck`, and the issue values `linearityMinStars` and `ensembleMinStars`. Detection and photometry results are unchanged. See [the algorithm](ALGORITHM.md#photometry-8-3).

- **The ensemble fit stops on the whole correction (photometry change; additive API).** The fit stopped when no frame's zero point moved by more than 1e-5 mag, even while its plane term was still moving. It now stops when the predicted correction `Z + a*x + b*y` has changed by less than 1e-5 mag at every usable measurement, and still stops after 15 iterations, keeping the last result. New telemetry: `PhotometryTelemetry.ensembleIterations`, `ensembleConverged`, `ensembleLastChangeMag` and `ensembleIterationLimit` for the final main fit, and `apertureSolvesAtIterationLimit` for the 0.7, 1.0 and 2.0 x FWHM fits; the text report has an "Ensemble fit" line. Reaching the limit changes no verdict. On the 18 reference datasets no verdict, frame, aperture choice or candidate changed, and corrections moved by at most 2e-5 mag: the old rule had stopped at most two iterations early, within 5e-5 mag of the settled correction. The final main fit reaches the limit on three not-ready sessions, two of which never settled under the old rule either. Run time is unchanged. See [the algorithm](ALGORITHM.md#photometry-9-3).

- **Streak masks in skipped frames no longer depend on piece order (photometry change).** When a streak track skipped a frame, photometry masked the stars at a position interpolated from one piece of each neighbouring frame and in the shape of one piece, both picked by their place in the track's list. With a fragmented or flashing trail, the same pieces in another order masked other stars. A neighbouring frame now enters the interpolation as the length-weighted centre of its pieces (a piece shorter than a pixel weighs one), and the shape is that of the piece in the nearest observed frame closest to the interpolated position, with a fixed geometric order breaking ties. Pieces are not merged into one footprint. Observed frames, mask reach, linking and detection are unchanged. On Klangwolke-2, two streak tracks gave 2 and 29 different masks over 40 piece orders and now give one; 120 stars gained or lost one usable measurement, two borderline stars became REJECTED candidates, and the high-confidence and possible candidates are unchanged. The other 17 reference datasets are unchanged. See [the algorithm](ALGORITHM.md#photometry-7).

- **LINEARITY ignores flags on excluded frames (photometry change).** The candidate gate failed a star for any `SATURATED` or `NONLINEAR` flag in its light curve, including flags on frames the analysis had already excluded, which supply no evidence. It now counts only frames without `FRAME_EXCLUDED`, still including measurements on those frames that were left out of the curve. The historical flags stay on the curve. On the 18 reference datasets no result changed: no candidate failed LINEARITY only through excluded frames. See [the algorithm](ALGORITHM.md#photometry-11-4).

- **Rejected frames no longer shape star qualification (photometry change).** Frames that the registration check or check B had already excluded still counted in the contaminated-shape statistics, the mostly-nonlinear star exclusion and the median-SNR star exclusion. Check B also flags `NONLINEAR` on the frames it rejects, so a star could be excluded for the very frames that were dropped. These three now count only the frames still active; excluded frames keep their flags and are still judged for contamination. New package-private `VariableStarAnalyzer.starExclusions`; no public API change. On the reference data, M81 Kumar scores 73 more stars (all 73 previously failed only the SNR median through excluded frames) and its candidates go from 10/18/22 to 9/19/20 high/possible/rejected: a borderline high-confidence star without a VSX match (Stetson J z-score 5.12 to 4.89) becomes constant as the magnitude neighbours change, one possible candidate is added, and all seven VSX-matched high-confidence candidates stay. m5-reg and Eagle-noisy change a few stars' SNR qualification but no candidate; Klangwolke-2 is unchanged. Contamination tolerances no longer widen with excluded frames, so retained frames get about 3 % more `CONTAMINATED` measurements on M81 Kumar; a session with fewer than 5 frames left after check B flags none. Not-ready sessions keep their verdicts. See [the algorithm](ALGORITHM.md#photometry-9-1).

- **Light curves carry their own aperture's errors (API change).** When a brightness range was measured in the 0.7, 1.0 or 2.0 x FWHM aperture, its light curves got that aperture's residuals but kept the main aperture's `magError`. Every aperture now gets its sky-noise error from the same formula, and a curve carries the errors of the aperture that supplied `deltaMag`. New: `StarLightCurve.apertureFwhmFactor`, `apertureMinRadiusPixels` and `apertureMaxRadiusPixels`. `PhotometryApertureChoice.radiusPixels`, the factor times the session FWHM rather than a radius any frame used, is replaced by `minRadiusPixels` and `maxRadiusPixels`, the radii on the frames used. Check B, the SNR cut, the aperture choice, residuals, scores and tiers are unchanged; on the 18 reference datasets only the errors and the new aperture fields changed. Klangwolke-2 measures 42 of its 69 reported candidates in a smaller aperture, and M81 Kumar all 28; their errors are about 0.6 to 0.8 times the main aperture's. See [the algorithm](ALGORITHM.md#photometry-11).

- **Faint-streak search (detection change, on by default).** A second, streak-only extraction of the kept frames on copies smoothed with a Gaussian the size of the stars finds trails too faint for the normal extraction (1-2 sigma per pixel). Its streaks are added after the normal streaks with normal priority: a normal streak detection stays in its track, tracks only gain faint pieces or merge through them, and a faint-only single-frame streak needs no peak gate. No other result receives its objects. New: `DetectionConfig.enableFaintStreakSearch`, `DetectedObject.fromFaintStreakSearch`, `PipelineTelemetry.faintStreakSearchTelemetry` (`FaintStreakSearchTelemetry`), `PipelineTelemetry.Stage.FAINT_STREAK_SEARCH`, `StageId.FAINT_STREAK_SEARCH`, `DataArea.inset` and a `TrackLinker.findMovingObjects` overload; existing signatures are unchanged. With the switch off, results are identical. On the reference data it found the Integral trail, and new or longer real trails on 7 of the other 18 datasets, lost no normal streak observation and changed no point detection; see [Faint-streak search](ALGORITHM.md#135-faint-streak-search).

- **Optional Auto-Tune observation (additive API).** `CalibratedAutoTuner.tune` and explicit-options `calibrate` accept an optional `AutoTuneObserver`. Lazy `AutoTuneSnapshot` callbacks expose read-only borrowed images, masks, sampling regions and actual trial recovery/noise positions on the tuning thread or its joined workers. No snapshots are built when declined; callback failures are diagnosed and ignored. Existing signatures remain supported. Sampling, search grids, measurements and selected settings are unchanged. Registration analysis also offers an optional per-usable-frame callback.

- **Calibrated auto-tuner mask overlap capped at 0.90.** The candidate star mask overlap grid now tests `{0.5, 0.65, 0.75, 0.85, 0.90}` instead of testing up to `0.95`. At `0.95`, detections embedded up to 95% inside a star mask bypassed veto, producing false-positive single-frame anomalies from seeing fluctuations and star wings.

## 1.0.6 (unreleased)

- **Kept inspection masks.** `redetectFrame` now applies the star mask captured by `inspectTransients`, including its original jitter footprint. It previously rebuilt the mask from master stars with the current configuration's jitter, so editing master settings could unexpectedly veto different sources in an existing inspection. Ordinary pipeline detection and newly built references are unchanged.

- **Too few frames stop the run after quality control.** When quality control keeps fewer than three frames (`JTransientEngine.MIN_KEPT_FRAMES`), `runPipeline` now stops there and returns a completed result marked with the new `PipelineResult.tooFewFrames`, holding the quality-control telemetry, the drift points and the data area. Before, it went on with one or two frames: the tracker already returned no tracks, but the stacks, slow movers and photometry still ran, and SpacePixels rewrote the result afterwards. With no frame kept, the run used to fail at the master reference; it now returns this result too. The stage observer hears no stage in that case. `PipelineResult.Builder.tooFewFrames` sets the field. Runs that keep three or more frames are unchanged.
- **Stage observer (JA-09).** A new `runPipeline(frames, config, listener, providedMasterStack, observer)` overload hands each finished stage (`PipelineStage`: master reference, slow movers, tracking, common motion, residual analysis, photometry) to a `PipelineStageObserver` with that stage's own products. The observer is called on the pipeline thread; its exceptions are reported and ignored. Results are unchanged with or without one.
- **Track linker split into stage classes (JA-06).** `TrackLinker` now orchestrates package-private stage classes; its public results and the detection results are unchanged.
- **The legacy score-based tuner is removed (JA-08).** `JTransientAutoTuner`, its options, the `LEGACY_TUNING` stage ID and the `AUTO_TUNE` rules scope are gone; `CalibratedAutoTuner` is the only tuner. `AutoTuneProfile` and `AutoTunerResult` are now top-level types in `engine`. `AutoTunerResult.bestTransientRatio` is renamed `noisePerMpixFrame`, and the fields only the legacy tuner filled (`bestStarCount`, `finalValidationTelemetry`, `effectiveOptions`) are removed.
- **Structured failures.** Engine and tuner calls throw `OperationFailedException`, which names the stage and the original frame where the failure happened, apart from completed empty or insufficient-evidence results and from joined cancellation. Stage IDs and frame identities are carried through worker batches, listeners, photometry and tuning. Interruption retains its flag; fatal errors propagate. Per-stage progress/outcome events remain separate JA-09 work.

- **Independent tuner operations.** The tuner captures immutable options, defensively copies grids/budgets and retains effective policy provenance. Explicit options support concurrent independent requests.
- **One worker pool per engine (JA-12).** Each engine, and each tuner call, owns a library-internal `WorkerPool` that runs its batches, stack rows and photometry within a scratch-memory estimate; nested batches run inline and a failure or cancellation joins sibling work. Removed, because no caller used them: borrowed executors and shared sessions (`ExecutionSession`, `ExecutionPolicy`, the engine constructors taking them), `OperationOutcome` and `OperationContext.capture`, the `CancellationToken` overloads of `runPipeline`, `detectTransients`, `generateMasterStackWithDetails` and `CalibratedAutoTuner.tune`, the tuner's `executionPolicy` option and session overloads, the executor parameter of `VariableStarAnalyzer.analyze`, and the deprecated `CommonMotionRejector.apply`. Cancel through `CancellationScope`. Outside an engine or tuner operation, standalone batches run on the calling thread.
- **Java and compatibility gates.** Java 21 toolchain/`--release 21` and bytecode checks for adopted config/execution boundaries run under `check`; the API consumer runs when the Central bundle is prepared. The coordinated SpacePixels matrix verifies source-built 1.0.5/1.0.6 artifacts with composites disabled and both Gradle/POM metadata. The 1.0.5 section below describes the predecessor unreleased source baseline, not a publicly available artifact; actual Central release availability remains unverified. No publication is performed by these checks.

## 1.0.5 (unreleased)

In preparation: changes since 1.0.4 are collected here and completed at release. Used by SpacePixels 2026.10-04.

### Detection changes

- **Anomalies on a streak's path join that streak.** A faint streak crossing a star changes the star's shape, and a tumbling satellite flashes along its path. Both were rescued as single-frame anomalies. An anomaly on a confirmed streak's line in the same frame, or where the streak's motion puts it in a frame the streak skipped or in the frame just before or after it, is now a piece of that streak. See [Anomalies on a streak's path](ALGORITHM.md#134-anomalies-on-a-streaks-path).
  - On the reference data, klangwolke-2 kept 22 of its 39 anomalies. The joined pieces were mostly a satellite's flashes and a trail crossing stars. The other datasets were unchanged, apart from one anomaly on klangwolke-1.
  - Photometry flags the stars a track crosses, so the stars these pieces cross lose their measurement in those frames.

### API changes

- **JA-01: captured configuration and shared rules.** Engine operations, both tuners and direct calibration capture private settings before processing. `DetectionConfigRules` exposes metadata for all 107 fields, operation-scoped structured validation and explicit alignment with field/rule IDs and adjustment directions. Non-finite consumed values are errors; finite legacy values, sentinels and scientific-policy conflicts remain accepted with advice. No serialized config fields/defaults change.
- Both tuners add `tuneSnapshot(...[, cancellation])` with detached fallback configs. Existing `tune` overloads preserve the same-reference fallback contract. SpacePixels consumes the rules for GUI, profiles, API and iterative requests. This is a coordinated local source integration; published-pair compatibility still needs release validation.
- `PhotometryGeometry` centralizes existing effective aperture/annulus pixel margins and exposes structured radius adjustments. Selection and crossing checks now follow expanded measurement radii instead of raw factors; configured factors remain unchanged. Targeted edge/crossing/flux tests cover custom/legacy factors. On the 153-frame africano-reg reference sequence, full scientific snapshots remain byte-identical to the pre-JA-01 baseline (excluding execution timings, hashing image/mask arrays).

- `TrackLinker.AnomalyDetection.lowConfidence` is removed. The anomalies it marked, those on a streak in the same frame, are now pieces of that streak's track in `PipelineResult.tracks` instead of entries in `PipelineResult.anomalies`.
